# 구현 플랜 (v2)

최종 수정: 2026-11-19

기준선 조건 하나가 수집부터 대시보드까지 통과하는 "세로 한 줄"(1차)을 먼저 끝내고, 하네스와 본 실험(2차)은 그 위에 올립니다. 지금 있는 의약품 패키징 485장(제품 152종)은 샘플이고, 추가 데이터는 같은 수집기를 다시 돌려 들입니다. 코드는 이 저장소에, 이미지·라벨·실행 결과는 사용자 PC의 `E:\` 드라이브에만 둡니다.

## 시작 전 확인 (사용자)

- 데이터 이용약관이 이미지를 외부 모델(Claude)로 보내는 것을 허용하는지. M3(첫 모델 호출)의 선행 조건입니다.
- 데이터 공식 설명서(라벨 유형 코드 정의)와 추가 데이터의 규모·도착 시점.

## 증분 데이터 규칙

- **수집은 멱등.** 항목 id는 이미지 내용 해시입니다. 같은 파일을 다시 넣어도 중복되지 않고, 수집마다 데이터 버전이 하나 생깁니다.
- **분할은 제품 단위 고정 해시.** 새 데이터가 와도 기존 제품은 개발용/평가용 사이를 옮기지 않고, 한 제품의 사진이 양쪽에 걸치지 않습니다.
- **평가셋은 버전으로 동결.** `eval-v1`은 바꾸지 않고 추가분은 `eval-v2`로 묶습니다. 버전이 다른 점수는 한 표에 섞지 않고, 대시보드의 모든 숫자에 데이터 버전을 표시합니다.
- **형식 어댑터 분리.** 패키징 형식 → 내부 표준 항목 변환을 어댑터로 둡니다. 화장품·다른 데이터는 어댑터만 추가합니다.
- **개인정보는 수집 단계에서 제거.** 촬영자 이메일·나이·성별은 표준 항목에 넣지 않습니다.
- **저장은 파일.** 트레이스·평가 기록·비용 장부는 모두 JSONL입니다. 필드 이름만 OTel GenAI 규약에 맞춥니다.

## 2차: 하네스와 본 실험 (M5~M7)

| 단계 | 만드는 것 | 완료 기준 | 모델 호출 |
| --- | --- | --- | --- |
| M5 지식베이스 | 식약처 공개 의약품 정보 수집, documentId·인용 부여, 스냅샷 버전, 정답 누출 검사 | 누출 검사 통과, 근거 documentId가 정답지에 연결됨 | 없음 |
| M6 하네스 | 후처리(검사만 모드) → 검색·검색 결과 검사 → 컨텍스트 순서·형식 → 이력 선별 순으로 하나씩, 각각 새 버전. CK 대조군 포함 | 단계마다 개발용 gate(정확도 비열등, 안전성, 비용, 실패율) 통과 | 개발용 |
| M7 본 실험 | 동결된 평가셋에서 C1~C4·CK 비교, 사전 등록한 검정 | 결과·비용이 대시보드에 기록, 질의 종류별 보고 | 본 모델, 평가용 |

M7의 선행 조건:

- **추가 데이터 도착.** 같은 제품의 사진은 서로 독립이 아니어서 실질 표본은 제품 수(현재 152)에 가깝습니다. 샘플 단계 결과는 파일럿으로만 보고하고, 신뢰구간은 제품 단위 재표집으로 계산합니다.
- **표본 크기·일정 재계산.** M3에서 잰 p_d, 건당 토큰, 구독 한도 소모로 다시 계산합니다.
- **분석 계획 사전 등록.** 주 가설, 주 지표, 보정 방법을 실행 전에 고정합니다.
- **모델 확정.** 파일럿은 Haiku, 본 실험은 Sonnet이 현재 계획입니다.

## 실행 위치

코드 작성과 가짜 모델 테스트는 어디서든 됩니다. 실제 데이터 수집과 구독 인증 모델 호출은 데이터가 있는 사용자 PC에서 실행합니다.
