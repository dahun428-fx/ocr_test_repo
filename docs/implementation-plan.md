# 구현 플랜 (v3)

최종 수정: 2026-11-19

v3는 2026-11-19 설계 검토 피드백을 반영한 판입니다 (바뀐 점은 문서 끝 참고). 기준선 조건 하나가 수집부터 대시보드까지 통과하는 "세로 한 줄"(1차)을 먼저 끝내고, 하네스와 본 실험(2차)은 그 위에 올립니다. 지금 있는 의약품 패키징 485장(제품 152종)은 샘플이고, 추가 데이터는 같은 수집기를 다시 돌려 들입니다. 코드는 이 저장소에, 이미지·라벨·실행 결과는 사용자 PC의 `E:\` 드라이브에만 둡니다.

## 시작 전 확인 (사용자)

- 데이터 이용약관이 이미지를 외부 모델(Claude)로 보내는 것을 허용하는지. M3(첫 모델 호출)의 선행 조건입니다.
- 데이터 공식 설명서(라벨 유형 코드 정의)와 추가 데이터의 규모·도착 시점.

## 증분 데이터 규칙

- **수집은 멱등.** 항목 id는 이미지 내용 해시입니다. 같은 파일을 다시 넣어도 중복되지 않고, 수집마다 데이터 버전이 하나 생깁니다.
- **분할은 제품 단위 고정 해시.** 새 데이터가 와도 기존 제품은 개발용/평가용 사이를 옮기지 않고, 한 제품의 사진이 양쪽에 걸치지 않습니다.
- **평가셋은 버전으로 동결.** 버전은 semver로 적습니다. 첫 평가셋 `1.0.0`은 바꾸지 않고 추가분은 새 버전으로 묶습니다. 버전이 다른 점수는 한 표에 섞지 않고, 대시보드의 모든 숫자에 데이터 버전을 표시합니다.
- **형식 어댑터 분리.** 패키징 형식 → 내부 표준 항목 변환을 어댑터로 둡니다. 화장품·다른 데이터는 어댑터만 추가합니다.
- **개인정보는 수집 단계에서 제거.** 촬영자 이메일·나이·성별은 표준 항목에 넣지 않습니다.
- **저장은 파일.** 트레이스·평가 기록·비용 장부는 모두 JSONL입니다. 필드 이름만 OTel GenAI 규약에 맞춥니다.

## M1a 완료 기준 (기록할 숫자)

"대체로 복원됨", "매칭률 높음" 같은 표현 대신 아래 숫자를 기록하고, 그 숫자를 보고 대규모 라벨링 전에 진행 범위를 정합니다.

| 탐색 | 기록할 숫자 |
| --- | --- |
| (가) 필드 복원 | 필드 종류별 복원 성공 수 / 대상 수 (제품명, 성분, 사용기한, 용법 등), 실패 원인 분류 |
| (나) 제품 매칭 | 정확 매칭 수, 모호 매칭 수(후보 여러 개), 미매칭 수 |
| (다) B 유형 후보 | B 유형 적격 필드 수, 그중 로컬 OCR이 오인식한 필드 수, 제품별 분포 |

(다)는 주 지표의 분모가 충분한지 미리 보는 것입니다. 로컬 OCR(PaddleOCR)만 쓰므로 외부 모델 전송이 없습니다.

| 탐색 결과 | 다음 행동 |
| --- | --- |

## 2차: 하네스와 본 실험 (M5~M8)

| 단계 | 만드는 것 | 완료 기준 | 모델 호출 |
| --- | --- | --- | --- |
| M5 지식베이스 | 식약처 공개 의약품 정보 수집, documentId·인용 부여, 스냅샷 버전, 색인 금지 대상 검사(CLAUDE.md 규칙 3) | 검사 통과, 근거 documentId가 정답지에 연결됨 | 없음 |
| M6 하네스 (단일 턴 2×2) | 출력 후처리(결정론적 → 재질의) → 검색·검색 결과 검사 → 컨텍스트 순서·형식 순으로 하나씩, 각각 새 버전. C2·C3·C4와 CK 진단 조건 | 단계마다 개발용 gate(주 지표, 해악 검사, 비용, 실패율) 통과. 재질의 비용이 조건에 귀속됨 | 개발용 |
| M6p 짝지은 파일럿 | 개발용 제품에서 Sonnet으로 C1·C4를 같은 필드에 실행 | 정오 불일치율(p_d), 제품별 편차, 건당 비용 보고. 제품 단위 검정력으로 M7 규모 산정 | Sonnet, 개발용 |
| M7 본 실험 | 동결된 평가셋에서 C1~C4 비교, CK 진단, 사전 등록한 검정 | 결과·비용이 대시보드에 기록, 보고 구성(연구 플랜 6절)대로 보고 | 본 모델, 평가용 |
| M8 이력 선별 실험 | 같은 문서에 대한 연속 질의 세션 정의, 이력 정책 비교 | 별도 사전 등록 후 실행 | 별도 |

M7의 선행 조건:

- **추가 데이터 도착.** 이미지 총량과 함께 새 제품 수, 제품별 B 유형 적격 필드 수를 확인합니다. 샘플 단계 결과는 파일럿으로만 보고합니다.
- **M6p 결과로 규모·일정 확정.** 주 효과의 95% CI와 검정은 제품 단위 짝지은 재표집으로 계산합니다. 정확 McNemar는 제품당 대표 항목 하나를 쓰는 별도 분석입니다.
- **분석 계획 사전 등록.** 주 가설, 주 지표, 주 분석의 분모(적격 필드 목록), 비열등 한계, 보정 방법을 실행 전에 고정합니다.
- **모델 확정.** 파일럿은 Haiku, M6p와 본 실험은 Sonnet이 현재 계획입니다.

## 실행 위치

코드 작성과 가짜 모델 테스트는 어디서든 됩니다. 실제 데이터 수집과 구독 인증 모델 호출은 데이터가 있는 사용자 PC에서 실행합니다.
