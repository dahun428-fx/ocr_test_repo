숫자가 커서 판정 규칙 탓인지 따로 확인했습니다. 실제 OCR 실패로 판단합니다.

| 확인 항목 | 결과 |
| --- | --- |
| 겹치는 OCR 줄이 없음 (누락) | 45 |
| 겹치는 줄은 있으나 글자가 다름 | 97 (그중 74건은 편집거리가 정답 길이의 절반 이상) |

큰 장식 글씨로 인쇄된 한글 제품명을 mobile 모델이 놓치거나 깨뜨립니다. 본문 크기 글씨인 유효성분명(8/157)과 사용기한(13/142)은 대부분 맞게 읽습니다.

### 관문 판단 (다)

- 주 지표의 분모(B 유형 OCR 오인식 필드)는 샘플에서 **150개, 113제품**입니다. 파일럿을 하기에는 충분하지만, 제품 단위로 개발용과 평가용을 나누면 평가용은 그 일부입니다. 본 실험 규모는 계획대로 M6p 파일럿에서 정합니다.
- 분모의 95%(142/150)가 제품명입니다. 첫 실험은 사실상 "깨진 제품명을 다른 단서(성분명, 분량, 제조사)로 찾아 고치는가"를 재게 됩니다. 유효성분명은 OCR이 거의 맞히므로 해 끼침 검사(OCR이 맞힌 필드를 망치는 비율)의 주 대상이 됩니다.
- 제품명이 깨져 있으므로 검색 질의를 제품명에만 의존하면 안 됩니다. 정답 제품명을 주는 CK 진단 조건이 검색 실패와 모델 실패를 가르는 데 꼭 필요합니다.
- 분모가 OCR 설정에 크게 좌우됩니다. mobile 대신 server 모델을 쓰거나 이미지를 줄여 넣으면 큰 글씨 인식이 달라질 수 있습니다. **OCR 엔진과 설정을 고정하기 전에** 제품명이 있는 182장으로 설정별 오인식 수를 비교해야 합니다 (M1b에 추가, 로컬 실행).
